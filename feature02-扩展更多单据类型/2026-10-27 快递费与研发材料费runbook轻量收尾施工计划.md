## 1. 目标与完成口径

将现有快递费、研发材料费类型参考补齐为**限定范围内可复用的 runbook**，接入已有统一入口与登记表，完成文档检查和独立情景走读。

本包复用已有代码和历史真实填写证据，以文档收尾为终点。新业务原件驱动的实际填写、真实保存及重开验证另按具体任务推进，不作为本包完成前置。已收尾的“报销单—公出自驾类”不在范围内；办公、福利及其他类型也不顺带接入。

## 4. 两份手册的具体施工内容

两份手册均应具备：适用/排除条件、必需与可选材料、字段来源、规则与核算、正式工具及操作顺序、异常停点、验证与交付。按需组织，不追求固定篇幅；通用规则只链接。

字段映射采用一张紧凑表，至少说明：**OA 字段或字段组｜本次来源及定位｜变换/计算｜核验与缺项处理**。覆盖本类型实际填写的主表、明细、费用、银行及物品档案等适用表；空表也写清来源理由。工具、参数和库函数以当前实现为准，不能发明入口。

### 4.1 快递费

1. 明确类别 `express / 快递费 / 15`，按真实模板及当前材料判断；模板姓名不代表当前操作人。修正旧文中“以模板页系统默认人员为准”的歧义：登录人来自当次认证，新页申请人/制单人来自当前新页观测。
2. 接受本次实际提供的结算表、统计表、运单、发票及收款依据；可互证的信息互证，不强求每类材料全部存在。没有运单号不补造，汇总与明细不重复计费。
3. 写清费用说明非空/为空两条路径、主要票据分配层及空表理由。有费用说明时按既有 `line_total` 语义核算，不能把行总额再乘次数；无费用说明时按现有明细路径处理。
4. 说明多费用行到报销明细及多收款人的对应关系，各层与主金额分别闭合。预算、日期、付款对象及金额来自本次证据，不能直接沿用历史样本。
5. 保留普通全额边界；非空关联、物品档案、部分票面报销、数量乘单价等未支持分支报告缺口，不绕过执行。
6. 给出已有正式工具的使用顺序、写前检查、独立 DOM 回读及交付要求。历史“G1—G7 全闭环”改为分层说明，不能把真实保存列为本包文档收尾门槛。

### 4.2 研发材料费

1. 明确类别 `rd_materials / 研发材料费 / 11`，限定现有物品档案行金额场景；不泛化为所有采购或研发业务。
2. 明确采购材料/统计、发票与完整档案编号的对应来源；没有编号或匹配不唯一时列缺口，不用名称近似匹配或借用旧模板档案。
3. 保留已验证的“物品档案新增→名称单元格打开选择器→完整编号精确选入”操作知识，区分工具栏插入与档案选择；核对编号、名称、购买人、价格和备注。只读带出字段不伪造。
4. `products.price` 为行金额和票据分配主要层；档案合计、报销明细及银行各自与主金额闭合，不把多个层次相加。关联/费用说明为空须有当次依据。
5. 数量单价、税额、折扣、运费等按材料解释；现行不支持的数量票据分配、新建档案、非空关联等继续列缺口，不因手册写了公式就宣布支持。
6. 区分供应商与员工收款，当前身份、预算与账户均核实来源。保存/重开要求引用公共入口，独立列为未来真实任务验证；不牵引本包实施保存工程。

## 5. 实施顺序与工作量控制

1. **核对差异**：只读两份手册及相关配置、正式入口、证据，列出真正缺失/矛盾之处；已有正确内容直接保留。
2. **集中编辑**：补齐两份 runbook，再更新登记与必要路由；不为每类建立重复 Skill，不重写公共框架。
3. **离线检查与独立走读**：按 §6 检查，发现具体问题才修订并复核受影响部分，不安排固定多轮施工。
4. **交付收尾**：写一份结果记录、同步 STATE，逐项报告 §7；代码缺口和后续真实任务单列。

本包可独立按文档维护执行，不要求启动 team-workflow。若用户选择 team-workflow 入口，按其合法接手流程和既有协作规则执行；不复用、恢复或清理旧自驾 workflow，不手改状态、失败字典或根任务。本计划不授予孤儿维护权限。

## 6. 轻量验证

- 检查两份手册及入口/登记的相对链接、字段来源、支持范围一致性，确认命令/参数及引用 API 在当前代码中真实存在；历史证据只核对必要字段，个人业务资料不复制进新手册或通用示例。
- 复用现有文档检查，在仓库根运行一次并保存结论：

```powershell
python -X utf8 -m unittest discover -s tests -p "test_skill_docs.py" -v
```

- 对两份 runbook 分别检查其字段表和操作顺序；现有文档测试未覆盖的内容人工式阅读核对由 agent 完成。此次纯文档工作不新增措辞匹配测试，不运行全量业务构建或真实浏览器测试。
- 由一名独立只读 agent 完成一次合并走读：每类一个支持范围内的代表请求，以及一个应停止/报缺口的变体。只给当前技能/手册、请求和最小必要材料，不提前给预期结论。检查其能否找到正确入口、说明字段来源和核算、识别缺口并给出正确下一步。
- 优先使用可用的代表原件；不足时可用明确标记“合成、仅文档走读”的匿名小例，不补造真实业务、不要求用户额外供料才能完成文档检查。缺失的真实材料只保留为日后业务验收缺口。合成例不写入业务 manifest，不生成可执行真实计划。
- 独立走读不调用线上入口，不读取认证文件，不写业务状态；只写结果记录中分配给它的走读部分。实现者整合发现，其他文件归主施工者；同仓库不得覆盖他人修改。
- 走读验证的是手册决策和可操作性，不标为真实填写、真实保存或完整冷启动验收。结束时记录审阅的最终文档哈希；后续有相关改动，仅复核受影响部分。
