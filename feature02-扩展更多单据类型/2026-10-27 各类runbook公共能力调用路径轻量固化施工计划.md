### G1：一次受锁保护的只读会话

1. 复用 `LoginProbe` 的真实身份发现、会话期限检查和现有锁。入口内已完成当次真实认证时，不再机械地先运行一次独立 `bpm_login.py`。旧登录 CLI 继续服务显式登录/扫码；填写 CLI 的 `--expect-name` 绑定不变。
2. 新查询入口允许传用户明确指定的预期姓名；未指定时自行发现，指定不符立即停止，不能自动替换预期。模板制单人、筛选人员、当前登录人分别处理。
3. 查询、必要翻页、精确详情核验以及用户要求的模板快照在本次同一 context 内完成。可在 `bpm/login.py` 增加小型上下文管理函数供查询使用，或在查询模块封装；不为此重构 `Probe.main` 或所有执行入口。
4. 成功探查后的本机会话元数据更新沿用现有方法；不输出整份 session record，不改变 30 天本地上限或服务端更早期限。单次失败要有结果与原因；finally 只关闭本入口创建的 context 并释放自己持有的锁。
5. 登录失效时返回明确缺口及现有登录入口，不自动长时间等待扫码或无限重试。认证入口、profile 锁、身份检查及异常清理均须有针对性回归。

### G2：报销单关键词查询与精确读取入口

建议新增 `bpm/query.py`，命令采用 `python -X utf8 -m bpm.query`，不增加根目录兼容壳。下列为**拟实现接口，当前尚不存在**；施工中如需小幅调整参数，在最终公共参考与验收中同步，不留下假命令。

```powershell
python -X utf8 -m bpm.query --keyword "外购样品" --limit 1 --run "20261027-query-01"
python -X utf8 -m bpm.query --number "15426104120" --snapshot --run "20261027-template-01"
```

上例仅示意参数；实际运行生成当次未使用的 run 标识，单号按用户指定值传入，不把示例常量写入程序默认值。

- `--keyword` 与 `--number` 二选一，至少一个必填；空参数不查全表。支持可选 `--creator`、`--department`、制单日期起止及 `--expect-name`，用实际观察到的筛选控件实现。人员/组织多候选不能任取首项。
- 默认查询当前账号有权访问的记录，清除系统自动带出的“仅当前制单人”筛选，并回读确认；用户明确给出的筛选必须保留。报告实际范围，不能宣称“全公司所有单据”。清除失败或部分筛选不能落实时，不静默按较窄范围返回“最新”。
- 已观察的关键词入口为主表备注、明细摘要、明细备注。它们分别查询并合并去重，语义是 OR，不能把三处同时填写后误作 OR。候选按完整单号＋UUID识别；输出实际命中字段/关键词，不把业务描述直接当成报销类别。
- “最新”默认按制单时间降序，明确时间口径，使用真实返回值；核实排序方向，不固定来回点击三次。每个查询分支取足前 N 个候选后再合并排序。遇分页边界、重复行或同一时间并列，必要时继续取证；同日显示不能冒充精确时间。真正并列时返回并列候选，不任意宣布唯一。
- 默认 `limit=5`，允许 1—20；读取设有限页数/时间预算并在输出中说明。零结果、部分分支失败、权限限制、翻页停滞、超预算分别留原因；未完成足够取证时不标“未找到”或“最新已确认”。不为找一张单普查全部历史。
- 精确单号保持字符串，不转整数、不前缀命中；单号/UUID不唯一即停止。仅定位时读列表与必要的只读详情头部，不遍历银行/全部子表。
- `--snapshot` 只用于 `--number`，复用 `bpm.template.fetch_template` 等现有主表/子表校验，保存来源和文件哈希；必要页面核实复用 `observe_template_view` 并保持同一 context。来自查询的 UUID 是定位线索，仍须实时核验主表。保持旧 `bpm_template.py` 参数和保存后重开路径的身份约束；不得把默认范围处理推广为保存后的宽松重开。
- 未登记类别可完成只读定位并报告实际类别；生成标准快照不支持时明确说明，并指向现有受控 `--research-raw` 研究路径，不注册新类型、不套相近配置、不自动导出整份敏感响应。
- 只调用已观察并在仓库已有依据的读取端点；页面“查询”可能发 POST，以实际查询动作及端点为边界，不把所有 POST 当业务写入，也不开放任意请求工具。

输出复用 `automation/runs/<run>/events.jsonl` 和 attempt 目录，增加小型 `query_result.json`：包含输入条件、实际范围、查询时间、排序依据、候选的完整单号/UUID/姓名/日期/类别/金额/状态/摘要/只读链接、取证是否足够及原因、证据引用。必要状态与既有 `NEEDS_INPUT` 口径衔接，不建设另一套状态机。失败同样落盘，且不覆盖旧 attempt。

本次已知失误作为具体修复依据：选真实可见下拉触发器；清空图标被遮挡时先确认页面原生清空行为并回读结果，不能改 DOM 值冒充筛选；响应匹配按解析后的 host/path 处理合法 query string，复用已有解析函数。操作前注册响应监听，避免漏事件后空等。

### G3：通用离线材料准备入口

建议在 `bpm/materials.py` 增加薄 CLI；如循环导入使独立 `bpm/materials_cli.py` 更简洁，可用后者并同步文档。拟实现命令：

```powershell
python -X utf8 -m bpm.materials prepare --source "本次原件目录" --out "独立的新派生目录"
```

1. 无需 OA 登录、人员姓名、模板单号或内部 task JSON。复用 `prepare_dual_materials`、`inventory_materials`、`extract_structured`，生成现有 v2.0 双根 manifest，不建立第二套材料格式。
2. CSV/XLSX 保留原始单元格定位和字符串语义；数字长编号、公式缓存缺失/不可信、公式无法可靠求值须显式待复核。公共说明同时区分 `extract_structured` 与 `extract_workbook` 的现有能力，不将有限 SUM 重算描述为完整 Excel 计算引擎。
3. 文本 PDF 调 `extract_pdf_text` 保存原始行、页码和区域，通过 `register_derived` 绑定原件哈希；使用现有原始提取角色，不写 reviewed=true。无文本页、混合扫描页、图片、受限/损坏或未支持文件登记具体缺口，清晰件继续处理。
4. 渲染与视觉复核复用 `render_to_files`、`review_pass` 等现有 API，在公共说明给出最小可运行用法及所需来源字段。本轮不增加 OCR 引擎，不默认渲染所有清晰文本页，不把 `barstub` 用于真实票据，也不让一次提取自动冒充独立复核。
5. 文件哈希去重只表示字节相同；同票不同扫描的业务身份去重仍需已复核票号等事实。同金额不同票不得合并；材料行也不能机械转换成费用行。
6. 源目录与输出目录互不嵌套；拒绝受保护路径、逃逸符号链接/目录连接和覆盖既有派生目录。特别核实 `.pw-profile`、`.local-session`、`.git` 等均在读取/枚举前被拒；对本入口可达的路径保护缺漏作窄修，不扩大扫描范围。
7. 输出 manifest 路径、文件/重复文件/解析数量、待复核清单及下一步入口。命令完成仅代表材料准备完成，不宣称事实齐备、可填写或 OA 已执行；不要求用户填写这些内部结果。

`bpm.collect.collect_materials` 目前针对通行费、油票及其汇总单，非 PDF 仅入映射，未知票种会报缺口。公共参考登记其真实范围并由自驾 runbook 按需调用，**不将它改名或包装为所有采购/快递/研发票据的通用识别器**。普通材料的语义重命名、副本归集待取得非自驾真实样本后另列小任务，本轮只保留来源映射与原件。

**R2：梳理材料、规则和字段映射。**

当前只提供了真实模板及开发目标，未提供本次外购样品的发票、采购/费用统计 Excel、付款依据或完整填写规范。先完成有依据的模板研究和初版手册；所缺业务事实集中登记，继续推进公共能力和可确定章节。以后收到原件/规则再补齐，不要求用户制作 JSON，不虚构已收到材料或已确认规则。

| 必须覆盖的映射 | 来源与核验要求 |
|---|---|
| 样品/订单/采购行 → 现有物品档案完整编号 | 明确材料列/原件页及当前档案证据；名称相似、历史编号、购买人相同不能替代完整唯一匹配 |

| 明细/采购付款 → 收款人及银行金额 | 结合本次垫付/对公付款事实核对；操作人、申请人、购买人、收款人分别处理，不默认互相相等或复制旧账户 |
| 主表类别、日期、摘要、主金额及空表理由 | 类别来自真实模板与本次场景判断；日期/摘要/金额来自本次事实；空关联和空费用说明各有当次依据 |

手册列出需要确认的具体口径及其影响：样品的报销范围/用途，现有档案是否覆盖本次采购，含税价/折扣/优惠/运费/退货退款/外币等材料是否出现及如何处理，按购买人/项目/预算/付款对象如何归组，票据分配、无票依据和关联要求。材料未出现的分支不强制用户逐项回答，也不默认允许；确实无法查证的关键口径一次集中提问，等待期间继续独立工作。

现有 `rd_materials` 限定范围为档案 `price` 已有明确行金额、空关联/空费用说明、普通全额票据分配及既有金额闭合。只有本次证据满足全部条件时才可沿用；不得将 quantity×unit_price、部分报销、非空关联、价格冲突或无现有档案包装为同一分支。实际出现这些情况时，在对应字段行写清缺口及停点。

## 5. 验收方法

### 离线与回归

- 查询有意义的反例：默认制单人限制、用户显式筛选不被清掉、同名组织歧义；三字段 OR 合并/UUID 去重；排序和分页、并列/缺失时间、部分查询失败；精确单号前导零/前缀/多 UUID；合法 URL query string；零结果与超时区分；身份不符/锁冲突/异常后释放自己资源；日志不泄露认证值。
- 材料反例：随机文件名、同内容多文件、同金额不同票号；文本 PDF 与空文本页混合、图片待视觉复核；前导零及公式待核；损坏件不吞掉其余文件；原件字节不变、派生来源可追溯、受保护路径/嵌套目录/连接逃逸/输出冲突拒绝。
- 复用对应模板、材料、提取、登录/session 和技能文档测试；不为措辞增加测试，不重复测试已经不变的业务公式。按 AGENTS 执行相关改动要求的单元检查；改过 `bpm/browser_probe.py` 必须先跑 `stage1_probe_selftest.py` 全绿再接 OA。其余全量离线构建仅在受影响范围需要时运行，不固定安排多轮重跑。

### 真实只读验收

使用新正式命令，不临时编写另一套驱动，不新建任何 OA 业务单据：

1. 以“外购样品”做关键词检索，验证范围与时间排序、候选去重和最新结果的详情。2026-10-27 已核实样本 `15426104120`（庄旭宏、研发材料费、2026-10-20）仅用于交叉检查；若出现更新单据，按当次实时结果判断，不硬编码它必须第一。
2. 按完整单号读取样本模板及必要只读页面，验证列表/主表/详情的单号和 UUID 一致。验证历史制单人不同于当前登录人的查询路径；若当次不具备该条件，另找已返回的合适候选或如实记录缺口，不伪造账号。
3. 使用无业务写入意义的唯一随机关键词查询，确认零结果与程序失败可以区分。登录过期、身份冲突等危险/不便制造的情形用离线替身验证，不主动破坏真实凭证。
4. 新命令每次正常运行只启动一个临时浏览器；全过程无现场改脚本、无点击隐藏控件的长超时、无反复全量枚举和固定三次切换排序。保留 600ms 稳定等待及必要回读；报告实测阶段耗时、启动和重试次数，不设无依据的固定秒数 SLA。
5. 另选一种非自驾材料的匿名离线夹具（如普通采购票据 PDF＋统计 XLSX）调用材料入口，核实盘点/提取/缺口路径。可复用现有 fixtures；合成测试不宣称非自驾票据业务解析、真实填写或保存已验收。

缺登录、权限或历史样本不可见时，继续完成离线实现和文档，保留未完成的真实验收项；不得把该情况写成全部通过。用户无需提供新业务票据才能验证这个基础包。

### 外购样品手册的独立走读

- 由一名独立只读 agent 合并审阅公共参考、新手册和路由，不另起浏览器、不读取认证文件、不改业务状态。主施工者负责实现与手册，审阅者只交问题和走读结论；不得覆盖其他人的修改。
- 给审阅者当前入口/手册及匿名代表材料，不提前给预期答案。覆盖：符合已有行金额范围的材料如何走到来源/对账检查；无完整档案编号或价格冲突时如何停止；出现数量分配/非空关联时如何识别未支持；缺规则/原件时如何交付具体缺口；其他研发业务如何保留原路由。
- 只核对正确性、范围和可操作性，不以固定测试数量、措辞匹配或大量轮次验收。发现实质问题后修订并复核受影响部分，记录最终文档哈希。走读不代替真实原件验证、真实填写、保存或完整整单冷启动验收。
