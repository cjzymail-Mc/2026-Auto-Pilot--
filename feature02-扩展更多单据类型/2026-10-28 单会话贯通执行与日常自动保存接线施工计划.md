# 单会话贯通执行与日常自动保存接线施工计划

编号：`BPM-FASTLANE-20261028-V2`。状态：**2026-10-28 按用户要求及独立评估修订完成，尚未施工；本版替代本文件原 V1，供后续施工使用**。本次修订不启动业务执行，也不恢复暂停的自驾工程。

本包回应用户 2026-10-28 对填单效率的反馈。用户期望的日常流程：**agent 快速填好单据 →（允许）自动保存草稿 → 保留填写页打开 → agent 完成一次全套自检 → 用户人工终审，审核通过后由用户本人流转**。用户原话要点："可以允许自动保存，但严禁流转/推送""我经常看到页面反复被打开、关闭""填单任务全部完成后，保留当前页面打开状态……然后 agent 再进行全套自检""最终审核的还是人工（我来审核）；审核通过后才会流转"。

本包定位为**日常执行体验与自动保存接线的第一阶段**，采用“完整自检、简洁交付”：减少跨入口重复启动与交接，接通任务准备和最终计划冻结的顺序，保留填写页，并在任务完成后立即交付结果。自动生成的必要 events、来源索引与哈希继续保留；不把人工或 agent 整理、复核工件的成本说成零，也不要求每单重复工程验收。**本轮不做回读缓存，不优化控件等待，不承诺单凭本包把五分钟填写压缩到三四分钟或一分钟。**

## 1. 依据与判断

- 需求来源为用户 2026-10-28 会话反馈（上文引述），与 [SKILL.md](../.claude/skills/bpm-fill-run/SKILL.md)「日常保存策略」节已登记的 `BPM-SELFDRIVE-20261027-A1` 增补（"用户已要求日常真实报销在填写并完整独立核验后自动保存草稿，严禁流转/提交"）一致；本次为用户对该策略的重申与流程效率补充要求。
- 独立核对代码和既有实测后的判断（2026-10-28）：

| 成本来源 | 现状证据 | 本包处理 |
|---|---|---|
| 跨入口编排 | 登录、查询、模板 CLI 分别管理浏览器；已有就绪计划的执行链已连续完成登录→填写→核验→调用保存控制器→驻留 | G1 接通前段依赖并共享会话，不把现有连续执行重复包装为新增能力 |
| A1 未接线 | SKILL.md 明示同任务自动授权编译尚未接通 | G2 明确先生成最终授权字段、后冻结计划与绑定记录 |
| 填写交互 | 20 行费用实例 UI 约 303.6s，单元格激活约 98.7s、增行约 30.4s；是本次样本的主要热点 | 控件提速留后续，本包不更改既有防御等待 |
| 回读与机器留证 | 同例最终独立回读约 0.61s、7 次截图合计约 1.35s、入口校验绑定约 0.52s | 保留新鲜回读；不为小额收益新增缓存失效机制 |
| 留页与交付 | 现有结果先落盘，再由原执行进程限时驻留；上层若等待进程退出，会延迟向用户交付 | G3 按完成事件交付，人工驻留单独计时 |

- 实测依据：[10 月 27 日 20 行费用实例 events](../automation/runs/20261027-074251-9d71443f/events.jsonl)；[10 月 23 日提速验收记录](../feature01-细化报销skill/2026-10-23%20提速施工验收记录.md)的 C0/C1 为 191.480s→155.226s，保留严格核验且减少重复操作后缩短 18.93%。不同单据规模不能直接比较；嵌套计时不能相加；这些样本不等于新材料到成单的端到端耗时。
- 查询入口单次约 10—15s 包含必要查询，不全是可消除的启动成本。施工前按当前代码记录阶段边界，不把旧 C0 当当前唯一基线，不编造本包预期节省比例。
- 现有基础：`fill_cli`（task 准备/validate-only/执行/`--resume-run`）、`LoginProbe`、`bpm.query`、`template.fetch_template`、`StructuredProbe`/`DraftUIAdapter`、`verify_snapshot`、`SaveController`、`--keep-open-minutes` 驻留。本包是编排层接线，不重写这些底层。
- 与 `bpm/chain.py` 的关系：它是离线复跑入口，不负责本包浏览器生命周期；本包复用 `bpm.request`、`bpm.facts`、`bpm.plan_generate` 等已有准备能力，补必要的前后衔接，不扩建 chain 家族。材料识别和复杂业务模型仍按既有 runbook 范围；缺少业务装配的场景不能靠新入口变成可执行。
- 红线兼容性：不修改 [AGENTS.md](../AGENTS.md) 红线 1 的条件本身——保存仍须"计划中有同 task_id 的 `save_draft` 授权"。本包把该授权的**生成方式**从人工逐单编写变为策略编译器自动生成并落盘绑定，正是 SKILL.md 既有设计意图："日常策略须编译为本次请求、同 `task_id` 的 `save_draft` 授权及来源/哈希绑定，再调用现有 `SaveController`；不能把一段策略文字当作已经完成授权。"用户明确"只填/暂不保存"时仍执行 `fill_only`，该优先级不变。
- **本计划文档本身不构成对任何具体单据的保存授权**；真实验收对象须用户当次提供（见 §5）。

## 2. 施工边界与交付

本轮交付：一个日常贯通执行入口（任务准备／已就绪计划两种明确分支）、A1 同任务授权编译器、同会话只读副页全量核验、完成后立即交付及限时保页、阶段计时、必要入口文档同步、一份收尾结果记录。不新增多档配置中心，本轮固定采用“完整自检、简洁交付”。

业务范围限现有已支持的 travel、express、rd_materials 子范围，按 runbook 与本次来源逐项判定。自驾装配缺口、外购样品材料／业务口径缺口和办公／福利真实页面范围不因公共入口上线而解除；类型注册或 `executable` 标记不能代替场景就绪。

**不放宽项（保留清单，逐条验收）**：

- `click_guard` 硬禁令：保存并提交、发送、提交、流转、审批、暂存、贴票、上传全部继续禁止；不自动确认未知对话框；不直接写接口。
- task-registry 防重复保存：`SAVE_INTENT`/`SAVE_UNCERTAIN`/`SUCCESS_DRAFT_SAVED` 优先进入只读核实；不重复保存、不另建单、不删 registry 或换 task_id 绕过。
- 金额 Decimal 三向闭合、选择器精确唯一命中、终局独立 DOM 回读不信任写入缓存。
- 凭证与会话隔离：`.pw-profile/`、`.local-session/` 不入 Git/日志/报告/工件；30 天本地复用与写回纪律不动。
- 稳定机制：600ms 轮询、Tab 失焦、行级重复回读、不承诺固定耗时。
- 保存成功报告仍须唯一新单号/UUID、未提交状态、重开持久化**全量**回读；终局、截图前后与点击前的新鲜检查保留。

**不做清单**：不恢复暂停的自驾工程（含餐补计划、公出匹配、Excel 回填另列）；不改 workflow helper/状态机；不加常驻服务、通用恢复机制、多 agent 并发；不扩建 `chain.py` 离线家族；不接办公/福利真实页面；不建跨天会话复用新机制。留页仍沿用 `--keep-open-minutes`，本阶段是限时保页，不宣称“无限期留到用户关闭”。

## 3. 必做实施项

### G1：单会话贯通执行入口

1. 统一日常入口定为 `python -X utf8 -m bpm.oneshot`，编排模块为 `bpm/oneshot.py`；复用底层函数，不在其内部依次执行登录／模板／填写 CLI 来伪装共享会话。输入继续使用现有 task/fill-plan、材料清单及事实／蓝图契约；内部工件由 agent 生成，不要求用户编写 JSON。
2. 必须区分两条路径，不能把“已有计划直接执行”冒充材料到单据全贯通：

   | 输入分支 | 顺序与边界 |
   |---|---|
   | 本次任务及准备工件 | agent 先完成可离线的原件理解、事实提取和已有场景字段映射；单会话取得当前身份→按完整单号 live 读模板→用本次观察补齐模板决策及尚未冻结的派生事实／蓝图→现有生成器产出最终计划并编译授权→冻结与验证→填写。不得先冻结计划再覆盖其中的模板快照。 |
   | 已就绪 fill-plan | 保持输入计划、来源及授权原样，核实当前身份后复用已有连续执行链；不无条件重读模板，不把已有 `fill_only` 计划静默升级为保存。确需 live 核对时，新观察单独留证；发现业务差异停止，不覆盖绑定快照或原计划。 |

3. 任务分支须接通至少一个现有支持场景的“同会话模板读取→最终计划生成→执行”。材料事实可提前准备，依赖当前身份／模板的最终字段、来源和授权在观察后绑定；按现有 FactSet/复用矩阵/生成器生成，不能仅替换哈希使旧值通过。未知规则、缺原件或尚未实现的业务装配返回具体缺口，独立可做的离线工作继续。不新增通用材料理解引擎，不宣称所有场景自动理解已完成。
4. 共享会话：一个业务编排执行者持有 context、锁及自己创建的页面；各步骤借用会话，借用方不得再次 launch、重复加解锁或关闭整个 context。`StructuredProbe` 的会话借用接口与 `DraftUIAdapter` 的页面参数应正式接入代码，不用运行时 monkeypatch。原页与恢复的他人页面分别识别；只能操作本任务页面。
5. 正常已认证路径的业务浏览器实例／context 各一次。保留与 `LoginProbe` 等价的真实身份探查、预期身份不符拒绝及本机会话记录写回。真实新扫码继续使用无旧凭证注入的全新临时 context，按既有登录规则执行；不得为满足“context＝1”恢复失效凭证或强制使用持久 profile。扫码例外单独计时、记录实际数量，不伪报正常复用路径达标。
6. profile 锁由同一所有者取得并持有到本任务会话结束，含 G3 驻留期；正常收尾在 `finally` 释放自己持有的锁。只读副页不另加同 profile 锁。异常残留沿用现有判活与归属机制，不删他人锁；不自建通用孤儿恢复工具。
7. 中断处理按 §3 的状态表执行，不能统一转成 `NEEDS_INPUT`。`--resume-run` 保持计划／操作人／配置哈希原绑定，不承诺自动恢复未保存页，不换 task_id。
8. 现有 `bpm_login.py`、`bpm.query`、`bpm_template.py`、`fill_once.py` 的准备／验证／执行／恢复入口保留兼容。新入口内的等价就绪检查可直接复用实际校验函数并留结果，文档说明其契约；旧 `execution_ready` 的 validate-only 子进程契约不暗改。

### G2：A1 日常自动保存授权编译

1. 输入为既有 A1 日常策略来源＋本次用户请求／用途＋本次材料与身份，不从历史模板、旧任务或其他人的授权继承。仅在本包支持范围且本次来源、规则与执行条件就绪时编译；缺真实用途依据则报告缺口，不能凭“没有 `test_context`”认定为真实可保存任务。
2. 三分支：真实日常任务且用户无“只填／暂不保存”覆盖意图→生成同任务 `save_draft`；用户明确只填→`fill_only`；测试、回放、占位或合成任务→强制 `fill_only`。用途依据来自本次请求和材料上下文，测试使用真实历史材料也仍属测试，不靠删除标记变成真实单。
3. 编译顺序固定为：**检查既有 run／registry 与请求意图→形成待冻结最终计划（含授权字段）→完整来源及金额校验→计算最终 plan_hash/config_sha256→落盘最终计划和授权绑定记录→执行绑定核对**。计划内 `authorization` 保持现有 schema；独立授权记录包含策略／请求来源引用、编译时间、task_id、最终 plan_hash、config_sha256、操作人绑定。
4. 授权记录是 run 内独立派生产物，不把含 plan_hash 的记录反向嵌入该计划或其已绑定 manifest，避免自引用哈希；政策／请求来源先按现有方式登记，执行时验证记录与最终计划的四绑定。计划冻结后不能再补字段、改授权或刷新模板造成哈希漂移。
5. 同一请求重试复用已冻结产物与授权记录，不用新时间戳重新生成不同计划。未冻结准备阶段可因新证据重新生成；已有执行绑定／填写意图／保存意图后发现身份、配置、计划或请求冲突，按原状态停止或只读核实，不自动重新编译改绑，不另建单。
6. `SaveController` 与 adapter 的身份、来源、配置／计划哈希、金额闭合、终局截图、截图前后及点击前的新鲜核验保留；仍至多一次唯一精确“保存”。授权编译不是守卫放宽。
7. 保存成功必须取得唯一新单号/UUID、证明未提交、重开持久化全量回读通过；否则保留真实失败／不确定状态，不用 toast 或“点击成功”替代。

### G3：完整新鲜核验、立即交付与限时保页

工程顺序为：填写完成→终局完整自检→有授权时保存草稿→只读副页持久化全量核对→**立即发布并向用户交付结果，主 tab 继续驻留供人工终审**。`fill_only` 在终局核验后直接交付并驻留。保留填写 tab 指不由 agent 为核验导航／关闭它；OA 保存动作自身产生的合法路由跳转如实观察，不阻止或伪造，交付时显示实际保存后的页面。

1. 终局独立 DOM 回读核对全部行数、身份、全部字段与 Decimal 金额闭合；不信任写入缓存。保存前既有新鲜检查继续执行。**本包取消原 V1 的回读缓存／合并项**；没有新的 agent 写入日志不能证明人工输入、异步联动或系统回填未改变页面。
2. 保存后仅在同 context 新建本任务只读副页，按真实观察到的路由／精确身份打开，继续调用 `verify_snapshot(..., phase="after_save")` 同等全量核验；除单号、UUID、未提交状态外，全部计划字段、行数与金额都须通过，不降为关键值抽查。观察、必要截图与核验工件齐备后，在 `finally` 关闭自己的副页，主 tab 保持；副页失败保留 `SAVE_UNCERTAIN`。副页所需精确查询不得通过复用 helper 意外导航主 tab。
3. `DraftUIAdapter` 明确各操作使用的 page，保存按钮只属于主 tab，保存后读取／截图属于副页；不长期切换共享 `probe.page` 造成错页保存、取证或清理。主／副页角色在事件中用本次非敏感标识区分，不能借机导出会话元数据。
4. 任务终局结果和 `probe_end` 或等价完成事件先原子落盘，再进入驻留。agent 使用宿主已有后台执行／通知能力运行任务，在完成事件后读取权威结果并立即回复；不得等待驻留进程退出，也不把长篇报告生成放在用户可见完成之前。此处后台进程仍是本任务执行者，不新增常驻服务或调度角色。
5. `--keep-open-minutes` 保持默认 45、既有可调范围；本轮真实交付使用正驻留值，明确告知保留期限。执行期间和驻留期间由同一进程继续持有 profile 锁，驻留时不再业务写入；用户提前关闭本任务页时可按既有清理规则结束。期满只按合法生命周期关闭本任务拥有的页面／context，不能关闭仍受保护的他人恢复页。
6. 同 profile 下一任务在驻留所有者存活时应报告占用，不绕过锁并发启动、不强关原页；当前不承诺保留上一页同时接下一单。用户驻留期提出追加修改按新请求处理，不复用过期核验结果或再次触发自动保存；缺少编辑接线时如实报告，不能要求换 task_id 绕过。无限期留页、多单共存或驻留中接单另作后续范围。
7. 可捕获的业务／网络错误保留主 tab 并按真实状态交付，继续既有驻留纪律。进程被终止、浏览器崩溃等情形只能依据已经落盘的状态恢复诊断，不承诺原页必然存活；不清失败历史，不强行重建未保存页。

### 中断与重试状态表（G1—G3 共用）

| 边界 | 应返回／保留的状态与后续动作 |
|---|---|
| 未开始填写且缺材料、规则或来源 | `NEEDS_INPUT` 和具体缺口；补齐尚未冻结准备工件，已有执行绑定的重试仍须原哈希一致 |
| 登录失效、需扫码或身份不符 | 保留既有 `WAIT_HUMAN_LOGIN`／身份冲突语义；不改预期、不继续旧身份任务 |
| 已有未保存填写意图／页面 | 仅盘点并返回 `NEEDS_INPUT`；`--resume-run` 不承诺自动续填，不另建单 |
| 终局回读不一致 | 保留 `READBACK_MISMATCH` 与差异、主页面；本轮不新增自动纠错循环 |
| 已写 `SAVE_INTENT`、点击后结果不明、已保存但持久化核对失败 | 保留既有保存 journal 及 `SAVE_UNCERTAIN` 等真实状态，只读核实；严禁重新点击保存 |
| `SUCCESS_DRAFT_SAVED` 后再次调用 | 只读核实原单；不得改绑授权、另建或再存 |
| 进程／浏览器异常退出 | 依据原工件、执行者、锁、registry 和页面诊断；按上列阶段处理，不清理历史伪装新任务 |

### G4：耗时与体验度量

## 5. 验收方法

### 离线与回归

- 两分支：任务分支必须先取得本次模板／身份再冻结最终计划；已就绪计划分支不刷新绑定或升级 `fill_only`。模板内容漂移、身份不符、材料缺口及未支持场景停止；旧 CLI 行为回归。
- 授权：三分支、真实历史材料用于测试仍不保存、无用途证据不自动授权、最终哈希一致且无自引用、重试复用、已绑定任务漂移拒绝；保存意图优先只读核实，来源可追溯且无敏感值进入 events。
- 会话／页面：只有所有者 launch/close/加解锁；借用者不关闭 context；副页读取、截图、异常清理与主页保存角色正确；副页失败不导航主页，不关闭他人页；扫码新临时 context 与身份／期限规则不受影响。
- 保存：保留新鲜回读及点击前检查；没有 agent 写入事件但发生人工编辑或异步变化时仍能拒绝失配。保存后非金额字段差异也须阻断成功报告，不能只验关键值。
- 故障注入在离线／合成环境覆盖写前、已有填写意图、`SAVE_INTENT` 前后、点击后响应丢失、持久化核验失败及进程中断留下的状态；只读核实不得产生第二次保存，不能全映射 `NEEDS_INPUT`。保留原失败历史与工件。
- 交付／驻留：用短驻留夹具验证先发布终局、上层收到结果即可交付、进程继续保页和持锁、下一任务占用拒绝、用户提前关闭／期限结束正常清理；驻留不计入技术耗时，不等待 45 分钟做测试。
- `click_guard` 硬禁令回归含贯通路径，真实链路不点击禁用动作。
- 相关测试先运行；收尾执行 `python -X utf8 verify_bpm_build.py`。该入口已包含探针自检与全量 unittest，不另强制再跑同一份全量 discover；只有新改动、失败或未解决疑点才追加对应检查。浏览器探针修改后的先自检要求仍适用。

### 真实验收（本包为真实保存的首次执行，对象须用户当次提供）

1. 先核对会话中是否已有本次真实任务（完整模板单号＋当前材料＋执行意图）；没有时仅集中列这项业务输入缺口，离线施工与文档继续。已有明确输入不要求重复提供，历史占位或回放单不得充当真实保存首验。
2. 使用本包支持且来源齐备的一个真实场景，优先走任务分支：材料事实准备→本次身份／模板→最终计划及授权冻结→填写→终局回读→唯一保存→副页全量持久化核验→立即交付→主 tab 驻留。events 证明生命周期与阶段耗时，原件及绑定不漂移。
3. 确认唯一新单号/UUID、未提交状态与全量持久化结果；agent 完成内容验收，用户后续人工终审不作为施工验收签字或手工保存步骤。记录主 tab 留存、完成事件后已交付及保留期限；不等待整个驻留期才宣布技术完成。
4. 不要求在真实保存点击附近故意断网、杀进程或重复新建；异常分支由上述离线故障注入覆盖。真实出现故障则按状态表处理。需要修复后的真实复验时先查 registry，仅在本次合法范围内开展，不能为凑“只运行一次”省略必要核实，也不能重新保存同一意图。
5. 单一场景真实通过只证明该场景与公共路径的证据层次；其他场景分别记录离线／真实状态，不外推为全部 runbook 已验收。无真实输入时结论为“实现及离线完成，真实保存待验”，不得宣称本包整体真实验收完成。
