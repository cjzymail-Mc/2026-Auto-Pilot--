## 关键决策（已拍板，防走回头路）

1. 真实首验**优先走任务分支**（`--task`：同一会话身份→live 模板→授权编译→计划冻结→填写）；`--fill-plan` 仅用于已就绪计划，不重读模板。
2. 日常自动保存按 A1 策略（`BPM-SELFDRIVE-20261027-A1`）由 `compile_authorization` 编译为同 task_id `save_draft` 授权；用户明确「只填」时执行 `fill_only`。授权编译已实现，**不要求用户手写 JSON**。
3. 保存后的持久化核验走**同 context 只读副页**（重开读单），主 tab 不被导航；终局先 `result_delivered` 立即交付，主 tab 按 `--keep-open-minutes`（默认 45）限时保留。
4. journal 预检（浏览器前阻断 `EXISTING_SAVE_INTENT`）仅在任务分支**新开 run**；`--fill-plan`/`--resume-run` 沿用既有入口行为（SaveController 在途只读核实）——已终审核实，勿再按「全分支阻断」旧表述理解。
5. 历史占位/回放单不得充当真实保存首验；不为凑对比数据重复保存同一真实业务。

## 实施步骤（主线下一步；建议默认可带默认推进）

1. 向用户取得三项输入（缺任一即集中报缺口、不猜值）：①完整模板单号（参考的真实历史单）；②本次材料目录（原件 PDF/Excel/图片路径）；③执行意图（场景＋自动保存或只填）。
2. 离线：`python -X utf8 -m bpm.materials prepare`（如原件未整理）→ agent 核对材料、生成任务 JSON＋`facts_payload`（FactSet 载荷＋blueprint＋材料 manifest）。
3. 探查身份：`python -X utf8 bpm_login.py` → 以实测操作人生成 `--expect-name`。
4. 就绪检查：`python -X utf8 -m bpm.oneshot --task "任务.json" --expect-name "操作人" --validate-only` → 期望 `TASK_VALIDATED`＋编译出的授权模式（此时确认 save_draft/fill_only 与用户意图一致）。
5. 正式执行：`python -X utf8 -m bpm.oneshot --task "任务.json" --expect-name "操作人" --keep-open-minutes 45`；events 按 `template_live_read→…→plan_freeze→section_fill→independent_readback_verify→save_and_persisted_verify→result_delivered` 时间序取证（G4 计时）。
6. 交付：结果状态/金额与行数/异常/保存单号与未提交状态/保页期限；真实保存成功须证明唯一新单号/UUID、未提交、副页重开持久化回读。
7. 收尾：结果记录补真实首验结论（C12 转真实证据或如实留缺口）；STATE.md 快照同步；G4 与 20261027 基线（307.8s/20 行）做同口径对比，只报可比部分。
