已通过用户现有 Git Bash `claude-glm` 启动函数，完成5份真实材料的图片盲测、1份降清晰度副本测试、1次Claude Code Read路径复测、1次缺失字段约束复测；并保留前轮4次Flash合成图测试及1次GLM-5.3合成图对照。共13次独立CLI调用，均返回了请求的模型标识，无传输失败。

**5份真实材料的68个预设核对字段全部一致；降清晰度副本15/15；Read路径15/15。但原始通行费发票响应额外补了两个未在票面标注的数量值，因此不能把“预设字段全部一致”解释为“整个JSON零推断”。增加字段适用性规则后，单次复测将这两个值正确返回null。**

## 1. 通道、授权与盲测方法

- 用户Git Bash `.bashrc` 的Zhipu分支指向 `https://api.z.ai/api/anthropic`，主/副位置原来都映射 `glm-5.3`。本轮逐次显式传 `--model glm-5.3-flash`，没有修改启动函数、账号配置或两个正在施工的session。
- Claude Code版本2.1.299。每次都是新建、非持久CLI过程，使用safe-mode、无设置源、无MCP、禁用技能。凭证由现有启动函数在子进程中提供，不读出、不写入任何测试工件。
- 图片盲测通过stream-json直接传base64 image content block；工具全部关闭，初始化与结果证据均为 `tools=[]`、`mcp_servers=[]`、无工具调用。模型只收到图片及字段要求，没有PDF、文字层、标准答案、材料原文件名或历史会话内容。
- 原始PDF仅在本机以200dpi渲染为PNG，标准答案在调用之外留存。五份原件与既有事实层、全部输入图片的哈希均核验一致；测试后再次核对无漂移。
- 真实图片第一次发送曾被自动审批拒绝；用户随后明确授权这5份图片及其降清晰度副本发送到api.z.ai，本轮在授权后执行。历史拒绝与后续授权均保留于events.jsonl，当前已无待授权阻塞。
- 此处核实的是当前实际通道的输入、模型标识和输出，不是对服务端权重或内部路由的独立审计。

## 3. 正常agent Read图片路径

新增R01-glm-5.3-flash-read.json：起始消息只有R01.png文件名和字段要求，没有直接附图片。只开放Read工具，以restricted模式把文件访问限制在inputs目录；标准答案、PDF和其他仓库文件不在可读范围。

证据显示模型准确调用**一次Read**，读取指定PNG；工具实际返回**一个image/png图片块**，然后输出15/15一致的字段，耗时21.78秒，无MCP或其他工具调用。这证明当前Claude Code工具读图路径也可用。

保留原PNG哈希及工具返回图片块哈希/长度；工具返回图像的字节表示与原PNG不同，不将内部转换后字节不同误判为原件变化。图片块base64未复制进报告或结果JSON。

## 4. 额外输出审计与缺失字段复测

原R02输出还给了 `trip_count=1`、`invoice_count=1`；这两个字段未纳入原12项标准答案。独立检查原PDF，票面没有“行程数量”“票据数量”等数量标注。这些是模型补出的推断，不是票面直接抄录值。

据此增加明确规则：“只抄票面标注行程数量/票据数量/共X张票据；未标注必须null，不得因为看到一张发票就推断为1。”使用同一张已授权图片做R02N复测：原12项+两个缺失字段共**14/14**，两个数量都返回null，耗时10.53秒。

原始响应和复测响应均保留；这是观察到问题后的定向提示词复测，不是另一份独立样本，也不证明一次提示词即可彻底消除推断。其他未列入标准答案的额外字段不计入68/68，不宣称已做全响应完备验收。

## 6. 结论、边界与落地方向

当前通道的glm-5.3-flash已证明可以独立读取这批代表性真实票据图片及行程表格，包括换行站名、拆分票、长号码与高精度单价；正常Read路径也有实际证据。它可作为现有GLM主agent的视觉解析与复核工具。

继续优先读取有完整文字层的电子PDF；扫描/图片/文字层异常时调用Flash。模型输出必须经过字段适用性、票号去重、金额闭合和跨材料核对，区分“票面抄录值”与“推断值”；不能将整份模型JSON未经核验直接投入OA。必要时使用高分辨率或局部裁图复核，但本轮未单独测试裁图策略和坐标精度。

无需整体替换主施工模型或增加后台常驻session。可用一次性 `claude-glm --model glm-5.3-flash` 调用提供视觉能力，仍在菜单选择Zhipu；本次没有更改默认模型，也没有把测试工具自动接入生产报销skill。

这只是5份数字PDF渲染原件、1份派生图及少量合成图。每种条件主要为单次请求；Read与缺失字段测试复用了已有图片。不能把这些字段匹配率解释为生产准确率，也没有验证真实手机照片的光照/反光、手写、印章遮挡、多页、多段行程、任意新格式或像素坐标定位。耗时只是本轮单图观测，非时延承诺；未将CLI估算费用当实际账单。

## 7. 可审计工件

- benchmark.py：像素盲测与逐字段比对；真实材料默认需显式授权开关。
- read_probe.py：受限Read路径及图片块元数据记录。
- absence_probe.py：R02缺失数量规则定向复测。

- inputs/：本机测试图片；results/*.json：原始回答、实际提示词、模型/工具证据、逐字段对比。
- summary.json：当前汇总与隔离核查；events.jsonl：追加过程、拒绝/授权和测试事件。
