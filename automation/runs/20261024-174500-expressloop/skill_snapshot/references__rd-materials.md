# 研发材料费：现有物品档案与价格行额

`document_type=rd_materials`，准确类别“研发材料费”，API 代码 `11`。配置为 `automation/document-types/rd_materials.json`。现有物品档案行金额路径已接入代码，授权复杂历史回放的真实填写、档案选择与独立回读已通过，真实保存/重开尚未执行。

输入要求和通用来源契约见 [plan-contract.md](plan-contract.md)。取得本次模板、采购材料/统计、发票、报销范围、操作人及申请组织、适用预算与收款依据；区分供应商和员工收款，不把模板个人账户默认用于供应商。具体真实业务保存授权与施工授权分开。

三张样本均有 products，分别为 18、10、11 行，其 price 合计各自与报销总额精确闭合。实际页面标题是“物品档案”，字段为 code（编号）、name（名称）、purchaser（购买人）、price（价格）、description（备注）；未见数量/单位列。本版将 price 明确建模为档案行金额，不推导它是数量乘单价。

执行保留四张主表并增加第五表 products。按本次材料提供的完整 code 精确选入现有档案，实际控件先点物品档案“新增”，再双击名称单元格打开表格选择器，用完整 code 精确选档案。编号、购买人和价格为只读带出，备注为可编辑输入，逐项回读；工具栏“插入”是行插入，不是档案选择入口。不创建档案、不用普通输入伪造档案带出值。code 必须唯一且保留前导零，description 可为空但仍需来源。当前范围要求 products 非空、relations/costs 为空，后两表均需当次来源的不适用理由。

原件有数量单价不等于 OA 必须按数量乘单价存储。若 OA 接受行总额，逐条核对票面有效行金额及来源，不能把单价当总额；若要求数量乘单价，须同时实现 schema、Decimal 精度规则、来源、有效行额分配、独立 DOM 复算和保存后回读。当前数量票据分配仍拒绝，不标成免票绕过。

发票分配的主要费用行为 products.price；产品合计、报销明细合计、银行合计分别与表头相等，不把三个层次叠加。模板投影、来源、精确档案选择、独立快照和保存重开均接入该表；新增数量、未知业务列、额外或重复档案继续阻断。

含税/未税、折扣、运费及尾差按本次凭据解释，不默认税率或容差。单位/数量不清、采购表与发票冲突、部分票面报销、借款抵扣、附件/贴票/提交分别报缺口。多品类预算科目逐行选择。

真实验收须完成实施计划 G1–G7 及 G9 的实际档案选择、价格核对与重开。样本 15426104120 已在真实新页选入 18 条档案、填写 4 条明细及 4 条银行，各层 9,935.16 元；证据为 automation/runs/types-rd-complex-R2/attempt_001/evidence/independent_verification.json。该轮是明确授权、标记不保存的历史回放，不能证明新业务发票材料或真实保存验收。新关联、数量乘单价或没有物品档案的其他材料结构均需另行建模与验收。
