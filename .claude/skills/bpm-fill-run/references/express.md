适用于真实模板确认为 `express / 快递费 / 15`，本次材料按普通全额报销、无关联单据及无物品档案的任务。配置为 [express.json](../../../../automation/document-types/express.json)。费用说明可非空，也可有来源地明确为空；不能用“其他费用”或差旅模型替代。

## 材料与适用判断

- 业务执行需要本次完整模板单号、报销范围/说明、费用及日期依据、适用预算和收款依据。接受结算表、统计表、运单、发票中实际提供且足以支撑本次字段的材料，不强求每类文件全部存在；无运单号不补造。缺核心字段时集中列缺口。
- 票据需覆盖主要费用行；无票行必须另有本次适用的免票理由及来源，仅有结算金额不等于免票依据。可选汇总单、运单与明细用于互证，汇总和明细不重复计费；同票不同扫描按发票身份去重。
- 登录操作人来自当次真实认证；制单人/申请人来自当前新页观测。模板人员只代表历史，不用模板姓名推断当前角色；人员处理仍走统一入口。
- 本版排除非空关联、物品档案、部分票面报销、数量乘单价及数量票据分配、借款抵扣、附件/贴票/上传/提交。遇到这些分支停在缺口，不改类型或用免票绕过。

## 字段来源与映射

每个执行值按公共契约绑定 `path / locator / sha256`；CSV/XLSX 用行列/单元格，复核 JSON 用字段 pointer，原件用页码/区域。可互证值以 `corroborates` 校验；冲突不能任选其一。下表的空值、不适用理由也须取本次来源。

| OA 字段或字段组 | 本次来源及定位 | 变换/计算 | 核验与缺项处理 |
|---|---|---|---|
| 人员与公司：`applicant`、`identity`、`header.corpCode` | 当次身份依据、当前新页人员/组织观测；必要的本次代办依据 | 使用当前显示名，区分操作人、制单人、申请人 | 人员/公司/部门独立核对；未知、同名不唯一或预期不符时停写，不从模板换人 |
| 主表：`bizOrign / budgetYears / payType / currencyType / submitType / description` | 当前页面选项、本次费用说明/预算/付款要求的文件定位；模板只作经核实的稳定结构参考 | 类别精确为“快递费”；年度、币种、方式及非空备注按本次事实选取 | 不把 API 原码当显示名；预算年度不机械沿用旧单，缺依据先补证 |
| 主金额：`totalCost` | 本次对账后的费用事实；对应主要费用行 pointer | Decimal 精确求和，页面为系统计算值 | 必须为正并与明细、银行及适用的费用说明分别闭合 |
| 报销明细：`reimItem / digest / budgetNo / subjectName / cost` | 本次费用分组/摘要、预算依据及分组金额的行/单元格；历史预算仅作核实适用性的参考 | 多费用行按有依据的项目/预算归组；先选预算单再选科目 | 项目/预算唯一命中；摘要取本次来源；每组金额与所属费用一致，明细合计等于主金额 |
| 明细带出：`budgetDeptName / budgetItemName / budgetOwner` | 本次预算选择后的真实带出值，与预算依据核对 | 只读带出，不伪造或强写 | 独立回读预算部门、项目及预算归属；不一致停写 |
| 费用说明非空：`project / startDate / endDate / projectPlace / count / cost / reason` | 本次结算/统计/运单及业务说明逐行定位 | 日期规范为 ISO；`cost` 是行总额，`count` 是有来源的正数；不再相乘 | 项目精确匹配、起止日期有序；地点/次数/说明不得套差旅默认值，任一必需值缺失即缺口 |
| 费用说明为空、关联为空 | 本次业务范围及“不适用”说明的定位 | `costs=[]`、`relations=[]`；在 `table_applicability` 分别登记有源理由 | 空表键集合与实际空表一致；不能用空表隐藏缺材料。express 没有 products 表，不添加该键 |
| 银行：`payee / account / bank / bankCode / cost` | 本次收款名单、账户/完整联行号及各人应收金额的定位 | 账号/联行号保留前导零；按真实收款对象分配，开户行由选择器带出核对 | 多收款人与费用归属对账，银行合计等于主金额；账户不清或无法唯一选支行时停止 |
| 发票及免票覆盖（计划材料层） | 原件页/区域、复核 JSON 字段、结算对应行及免票依据 | 按下节唯一主要费用层分配；每张票全额、每行全覆盖 | 原件/复核哈希入同一 manifest；票面与表格冲突、重复票、缺覆盖均阻断 |

## 核算与空表规则

1. **有费用说明**：`amount_rules.costs="sum"`、`cost_amount_semantics="line_total"`。主要票据/免票指针为 `/tables/costs/行号/fields/cost`；Σcosts.cost = Σdetails.cost = Σbanks.cost = totalCost。次数不再乘入金额。
2. **费用说明确实不适用**：`amount_rules.costs="not_applicable"`，提供非空 `costs_reason`，同时为 `/table_applicability/costs/reason` 绑定本次来源。主要层改为 `/tables/details/行号/fields/cost`；Σdetails.cost = Σbanks.cost = totalCost。关联空表理由独立登记。
3. 多费用行可以按有证据的预算/项目归为多条明细，银行按收款人分组；在本次对账记录中留清“费用→明细→收款”的对应关系，不能仅凭各层总额相等掩盖错配。各层表示同一笔钱，不能叠加为主金额。
4. 逐票分配总和等于该票复核总额，逐主要费用行分配总和等于行金额；无票行用 `materials.no_invoice_rows` 的 reason/proof 覆盖。发票不能同时再分到汇总明细。日期、月份、金额及付款对象均来自本次材料。

## 正式操作顺序与停点

1. 先判断离线整理还是业务执行。业务执行按统一入口运行 `python -X utf8 bpm_login.py`，取得当次身份；定向读取完整模板号，确认类别与本范围，不沿用旧姓名。模板 CLI 为 `bpm_template.py --live --expect-name "操作人" --template-number "完整单号" --output "automation/runs/独立准备run/template_snapshot.json"`（运行时同样使用 `python -X utf8`）。
2. 由 agent 整理任务，运行 `python -X utf8 fill_once.py --task "任务.json" --expect-name "操作人"`。该步仅准备并返回 `NEEDS_INPUT`；继续完成原件提取/复核、票据分类去重、对账与来源绑定，不要求用户写内部 JSON。
3. 按上表确认费用说明分支、空表理由、多行与收款对应，生成 v1.0 计划。写前检查材料/模板/配置哈希、身份来源、精确选项、票据覆盖、各层金额及未决缺口；运行 `python -X utf8 fill_once.py --fill-plan "填报计划.json" --expect-name "操作人" --validate-only`。未通过不进业务填写。
4. 就绪后按本次意图运行 `python -X utf8 fill_once.py --fill-plan "填报计划.json" --expect-name "操作人" --keep-open-minutes 45`。正式执行器连续填写表头、明细、适用费用和银行，新增行后重新定位；不逐格派发脚本。预算先选单再选科目，支行按完整联行号选择并核对全称。
5. 独立 DOM 回读当前身份、类别联动、主表与全部表的全字段/实际行数、带出值及金额，检查额外/重复/缺失行。空表也必须真实存在且完整读取，隐藏或未加载不能算空。选择转账生成的当前申请人空金额银行行，仅当正式执行器的新页前后快照证明其来源时接受，不放行旧行或非零额外行。
6. 缺来源/唯一选项、材料冲突、未支持分支按 `NEEDS_INPUT` 停止；页面差异按 `READBACK_MISMATCH` 留证。保存、重开及异常恢复只按统一入口，不在本手册另建策略；本包不测试保存按钮。

上述 2—4 的分段命令可由单会话贯通入口替代（见 [公共能力调用参考](common-operations.md) §5）：`python -X utf8 -m bpm.oneshot --task "任务.json" --expect-name "操作人"` 在同一会话完成身份→live 模板→计划冻结→填写，授权按 A1/本次请求编译；实现＋离线验证，真实填写/保存待验。停点、空表与回读规则对两入口同等适用。

只读模板研究在列表默认范围排除历史制单人时，可使用既有 `--lookup-list "已采集API列表.json"`、`--observe-view`；缓存须唯一匹配完整单号/UUID，实时 GET 主表再次匹配。此回退不适用于保存后重开，后者按统一入口严格核对当前身份。
