# 出差单（行程安排与草稿）

适用于用户用行程明细截图发起的真实新「出差单」。使用 `/oa/evections` 列表和 `qd-evection-detail` 新建表单，由 `bpm.evection` 执行。差旅费报销走自己的 runbook。

## 日常流程

1. **从截图取本次事实。** 按图片顺序复核城市、日期、天数和工作事项，依据本次行程拟写事由。核实「出差明细」的开始、结束日期及时分；图片只有日期时，向用户集中确认缺失时分，不从历史单或默认值推断。工作交接、费用等未提供且非必填时保留默认空值。agent 准备内部工件，用户无须提供模板单号或编写 JSON。
2. **自动查历史参考并填写。** 用当前真实账号查出差单列表，优先同制单人、同申请人的合适历史单；近段日期无结果时可放宽同人的日期范围。只读查看匹配单据，参考结构和写法，不复用旧单的日期、时分、事由、费用、关联或人员。无适用参考时，使用新页带出的申请人、制单人、公司、部门、成本中心等默认值，加上本次已核实事实，继续填写。记录「无参考」和「查询失败」的区别；如登录或新页身份无法核实，先处理该缺口。
3. **保存草稿后提醒用户审核。** 按 [AGENTS.md](../../../../AGENTS.md#红线) 的真实出差单日常授权编译本任务的 `save_draft`，同一任务不再询问是否保存。当次明确「只填」「先审」「暂不保存」时用 `fill_only`。在会话中告知已核实的完整单号、「编制中」状态、明细起止时分，并提醒审核。按保存结果交付，不以按钮已点、弹窗或页面带出单号单独判定成功。

## 执行与验收

入口复用当前 OA 登录与独占 profile 锁。发现仍在填写或审阅的页面时保留现场；审批监控持锁时按已授权范围协调，退出后确认监控恢复，避免和填报并行。需要现场审阅时，启动前核实 Windows 进程使用当前交互桌面，交付时核实窗口确实可见。隔离桌面的 Chromium 即使显示或置顶，用户当前桌面也看不到。

`itinerary.json` 由 agent 生成。`image_sha256` 是本次图片的 SHA-256；`trips` 各行依次为出发城市、目的城市、开始日期、结束日期、天数、工作事项，均为字符串。日期用 `YYYY-MM-DD`，天数为含起止日的自然日计数，相邻城市须连续。城市先在实际选择器预查精确名称；重名仅在机场档案有唯一依据时选取，填写时再核对完整城市编码。

现有 CLI 的保存分支要求同一 run 有先前整表回读。日常保存由 agent 先完成只填回读，用最短驻留自然收尾，再核实原窗口已退出、同任务 registry 无在途保存意图，继续同 run 的草稿分支。用户不必在两个阶段之间操作。`--observe` 仅用于查看历史候选及空白新页结构，不能替代先前整表回读。明确先审的未保存窗口按既有恢复规则保留。

```powershell
python -X utf8 -m bpm.evection --image "行程截图.jpg" --itinerary "行程复核.json" --run "本次run" --expect-name "本次核实的操作人" --keep-open-minutes 1
python -X utf8 -m bpm.evection --image "行程截图.jpg" --itinerary "行程复核.json" --run "本次run" --expect-name "本次核实的操作人" --draft-request "本任务保存授权.json" --validate-only
```

校验通过后由 agent 去掉 `--validate-only` 执行保存。授权文件绑定 `task_id`、`mode=save_draft`、`allow_submit=false`、本次 `image_sha256`、`prior_attempt`、`prior_readback_sha256` 和确认的 `start`、`end`（`YYYY-MM-DDTHH:MM`）。`statement` 记录当次明确请求，或 2026-11-18 的真实出差单日常授权及本任务适用依据。未传入有效绑定授权时，程序仍只填不存。

保存分支当前只支持不派车、不关联票务、无费用的场景。保存前核实无单号新页、身份、整表行数和值、明细时分、空费用及出差事由，登记保存意图后一次点击「保存」。保存后用完整单号与 UUID 唯一定位，确认「编制中」并只读重开核对。出现额外弹窗或结果不明时保留证据，不自动确认弹窗、再次保存或另建。已有精确保存响应和先前默认字段证据时，用 `python -X utf8 -m bpm.evection_reconcile --run "本次run" --save-attempt "保存attempt" --defaults-attempt "已记录默认字段的attempt" --number "完整单号"` 只读复核；证据缺失时报告不确定，不新开单据补证。
