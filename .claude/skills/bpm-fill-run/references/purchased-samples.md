# 报销单—外购样品 runbook

外购样品是**研发材料费（`rd_materials` / 11）类别下的业务场景**：购买人先垫付采购实物样品，按现有物品档案行金额报销。类型结构、执行器与校验完全复用 [研发材料费 runbook](rd-materials.md)；本手册只补场景识别、字段映射与归组规则。公共查单/读模板/材料准备调用见 [common-operations.md](common-operations.md)。

**登记状态（2026-10-27）**：模板研究与初版手册已完成；本次外购样品业务口径（见 §3 待补清单）与真实原件尚未提供；新业务填写与真实保存**未验**。历史模板只读研究不证明新建页编辑已验收。

## 1. 适用范围

进入本手册需同时满足：
- 真实模板核实 `submitType` 为 `11 / 研发材料费`（`rd_materials`）；
- 业务证据表明是外购样品报销：摘要/明细摘要含"外购样品"类表述 + 采购实物样品的材料（订单、统计表、发票）或用户明确意图。

「外购」关键词、模板单号或人员本身**不构成**可填写判定；实证类别变化时保留只读并报告，不强映射为研发材料费。其他研发材料业务（非样品采购）走 [rd-materials.md](rd-materials.md) 原路由。

## 2. 输入要求

| 输入 | 要求 |
|---|---|
| 参考模板单号 | 完整单号，用于定向读取结构（`bpm.query --number … --snapshot`）；不绑定特定人员/行数/金额 |
| 本次原件 | 采购/订单统计（CSV/XLSX）、发票（PDF/图片，image_documents 分类）、付款依据；按 [common-operations.md](common-operations.md) §3 离线准备 |
| 操作人 | 本次真实探查发现；`--expect-name` 与实测一致，不沿用历史姓名 |
| 物品档案 | 本次采购样品须在系统**现有**物品档案中找到完整唯一编号；无档案的新样品登记缺口，不自动建档 |

## 3. 业务规则及来源

已实证（来源：指定模板 15426104120 的 2026-10-27 实时快照与只读页面核实，`automation/runs/20261027-common-accept-tpl2/`；单次观察，不当作制度）：
- **归组规则**：物品档案行按 `purchaser`（购买人）归组 → 每购买人一条报销明细（摘要「<购买人>外购样品费」），同一预算（budgetNo/预算项目）；档案行 `price` 为行总额，按购买人分组合计 = 对应明细 `cost`，全部明细合计 = 主表 `totalCost`（Decimal 闭合，实证 4 组逐人相等）。
- 档案行字段：完整编号 `code`、名称 `name`、购买人 `purchaser`、行金额 `price`；从档案带出，非本次手填。
- 关联单据、关联明细、费用说明均为空（历史研究与本次快照一致）；附件区有票据附件（该单 25 个，仅证存在性）。

**沿用 rd_materials 的限定范围**：仅支持现有档案 `price` 明确行金额、空关联/空费用说明、普通全额票据分配、金额闭合；超出即停（见 §6）。

待补业务口径（**未有本次原件前不虚构**，取得材料后逐项确认）：
1. 样品的报销范围/用途口径（是否全部采购项均可报、有无不予报销项）；
2. 现有档案是否覆盖本次全部采购（新样品无档案时的处理路径：补建档人工流程还是不报）；
3. 含税价/折扣/优惠/运费/退货退款/外币出现时的金额口径；
4. 归组是否恒为按购买人（多人合购单样品、单人跨预算采购的拆分）；
5. 票据分配、无票依据、关联要求是否与研发材料费通用规则一致。

## 4. 字段映射

| 映射 | 来源与核验 |
|---|---|
| 样品/订单/采购行 → 物品档案完整编号 | 本次采购材料列 ↔ 系统档案 `code` **完整唯一匹配**；名称相似、历史编号、购买人相同不能替代 |
| 档案 code/name/purchaser/price | 系统现有档案带出（只读带出字段）；与本次采购事实对照，冲突阻断 |
| 发票 → 样品/档案行 | 票号+原件哈希+页/区域+复核记录；同票多扫描去重（哈希），同额异票保留；分配按档案行金额普通全额，不与历史样本借票 |
| 档案行 → 报销明细/预算 | 按 `purchaser` 归组（§3 实证规则）；预算号/科目来自本次预算事实，不复制历史预算 |
| 明细/采购付款 → 收款人及银行金额 | 本次垫付（购买人=收款人）或对公付款事实核对；操作人/申请人/购买人/收款人分别处理，不默认相等、不复制旧账户 |
| 主表类别/日期/摘要/金额/空表理由 | 类别=11（真实模板）；日期/摘要/金额来自本次事实；空关联、空费用说明各有当次依据（沿用实证结构，若本次出现非空即超出支持范围） |

## 5. 操作步骤

1. `python -X utf8 -m bpm.query --number "<参考单号>" --snapshot --run "<run>"` 定向读取结构（或按关键词找参考单）；身份、范围、耗时见 `query_result.json`。
2. `python -X utf8 -m bpm.materials prepare --source "<原件目录>" --out "<新派生目录>"` 离线准备；复核 PDF/图片提取（渲染+独立视觉复核），生成事实与对账。
3. 按 §4 映射逐项核对：档案编号唯一匹配、按购买人归组、金额 Decimal 闭合、票据分配闭合；任一项不成立 → §6 停点。
4. 生成 v1.0 填报计划（计划形状与执行值来源契约见 [plan-contract.md](plan-contract.md)）并 `--validate-only` 离线校验后，走 [rd-materials.md](rd-materials.md) 的正式执行入口（`fill_once.py --fill-plan …`）。

## 6. 异常停点

| 情形 | 动作 |
|---|---|
| 新样品无现有档案编号 | 登记缺口停（不自动建档、不用相似档案替代） |
| 档案 price 与本次采购金额冲突 / Excel 与票面冲突 | 阻断，集中报告 |
| 出现数量×单价、部分票面报销、非空关联、非空费用说明、借款抵扣、附件/贴票要求 | 超出 rd_materials 支持范围：报告不支持，不套相近分支 |
| 实证类别 ≠ 11 | 保留只读并报告实际类别，不强映射 |
| 归组事实与 §3 规则不符（合购/跨预算） | 按待补口径 §3.4 停，待用户确认 |
| 票据身份不明/复核失败、金额不闭合 | 待复核/NEEDS_INPUT，不猜值 |

## 7. 验证与交付

- 离线：映射逐项来源核对、Decimal 闭合（档案分组=明细=totalCost）、票据分配闭合、计划 `--validate-only` 通过。
- 执行验收按 rd-materials 既有口径：真实 Chromium 填写、独立 DOM 全值/行数/金额回读；保存按 AGENTS 红线仅经专用授权路径。
- 交付缺口精确到字段/业务口径（§3 待补清单），不以"待补充"大纲交付；场景路由与登记状态见 [入口与未来扩展说明](../入口与未来扩展说明.md)。
