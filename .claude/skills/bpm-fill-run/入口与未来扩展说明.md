# 入口与未来扩展说明

本文件说明 Skill 文档框架、已固化 runbook 及未来扩展方式。统一业务入口为 [SKILL.md](SKILL.md)，按用户请求和本次材料加载对应 runbook。出差单从行程截图启动，报销按真实模板和业务材料路由。业务执行须遵守仓库 [AGENTS.md](../../../AGENTS.md) 与本次适用授权。

## 文档框架

以下路径相对于本 Skill 目录，新增手册沿用这一结构：

| 层次 | 位置与职责 |
|---|---|
| 统一入口 Skill | [SKILL.md](SKILL.md)，负责接单、路由、公共流程及安全边界 |
| 公共参考 | [common-operations.md](references/common-operations.md)（查单/读模板/材料准备/计划校验/执行/结果定位的正式调用路径）、[full-chain.md](references/full-chain.md)、[plan-contract.md](references/plan-contract.md)、[evidence-hash-semantics.md](references/evidence-hash-semantics.md)，说明通用链路、计划契约及证据规则 |
| 类型/场景 runbook | `references/<场景名>.md`，说明该类业务的识别条件、原件理解、金额规则、执行步骤与验收边界 |
| 实现及验收状态 | 仓库 [STATE.md](../../../STATE.md) 及其直接证据入口，记录尚未接通的工程与实际验证结果 |

AGENTS.md 保留长期规则和本文件指针；框架与手册登记在此维护，具体业务步骤写入对应 runbook，当前工程进度及恢复线索留在 STATE.md。

实现代码与诊断/验证工具的归类、旧代码路径映射见 [仓库目录与维护入口](../../../docs/repository-layout.md)。

## 未来新增或升级手册

1. 在对应 runbook 中补齐适用条件、原件与来源要求、金额规则、正式执行入口及验收要求。
2. 在 SKILL.md 增加按真实模板和业务证据判断的路由，按需补齐规则、执行适配与验证，不以文档路由代替实现。
3. 在本文件更新手册登记，并附与完成层次相符的证据入口；工程进度和待办在 STATE.md 维护。
4. 沿用统一入口及现有安全控制，无需提前创建空手册或另建一套入口。文档维护不自动启动施工或真实 OA 操作。
