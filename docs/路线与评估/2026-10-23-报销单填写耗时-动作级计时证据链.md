### 3.2 45 秒间隙定论：**真凶既非 H1 也非 H2/H3，是 `_pick_row` 选中态核验的 `get_attribute`**

- **证伪**：全 158 条 timing 事件中 **outcome=timeout/error 为 0**。`dialog_element_handle`（H1）全文件 6 处（L378/384/388/401/481/499），全 ≤22ms，其中单号弹表窗内 4 处；`dialog_close_click`（H2）147ms；`pick_option`（H3）5 条最大 4853ms，未涉入该窗口。
- **真凶证据链**：
  1. L365 `overlay_pick_row(关联单据/单据类型) dur_ms=45822 outcome=ok`（L367 外层 `overlay_pick`=45936ms）——45s 烧穿整段落在此，且窗口内无任何已埋点子动作耗时，即烧在内层未细包代码。
  2. 代码路径 `stage1_browser_probe.py:2020-2030`（`_pick_row`）：行点击 `row_loc.click(timeout=8000)` 成功后（~0.1s），**单据类型是 dropdown 浮层——点行即关浮层，行元素随浮层 detach**；随后选中态核验 `row_loc.get_attribute("class")` **无显式超时**，按 default timeout 等元素挂载烧满 45s 抛 TimeoutError，被 :2029 裸 `except Exception: pass` 吞掉 → `_timing` 边界看不到异常（outcome=ok），流程继续且**选点本身已成功**（fill_overlay_row 正常落盘、终局回读 29/32）。

## 4. 结论

1. **45s 间隙定论**：`_pick_row` 选中态核验 `get_attribute`（:2026）无显式超时 + 「点行即关浮层」的 dropdown 场景行 detach + `except: pass` 吞 TimeoutError。选点已成功，45s 是纯死等；**可安全缩短**（前置 count 守卫——`_cell_info` :1753（守卫在 :1754-1756）已有同型先例——或显式短超时）。H1/H2/H3 全部证伪（实测 ≤22ms/147ms/未涉入）。
2. **汇总行 ~101s 构成**：预算科目一格 91.8s（dblclick/click 各一次 `inp.fill` 默认超时死等，readonly 列挂不可操作 input，内层 except 吞掉）+ 正常列 ~19s。**可安全缩短**：预算回显列跳过通用写入循环（值由预算联动回填），或 `inp.fill` 前加 actionability 预判/显式短超时。
3. **本轮两大死等合计 ~137s（45.8+91.4），全数来自「无显式超时调用 + 内层自捕获异常」**——这类等待对 `_timing` 的 outcome 标记不可见（显示 ok），必须靠 dur_ms≈45000×N + 代码路径 + 离线机制复证识别；本轮已按此方法闭环，后续优化任务的验收应沿用（不能只看 outcome=timeout）。
4. **观测粒度限制**（如实声明）：`_timing` 只标跨段异常；激活循环内层、`_pick_row` 内部逐调用未逐一单独包裹——本轮两处归因靠「窗口内嵌事件排除 + 代码路径 + E1/E2 离线复证」三方互证，非直接计时点。费用明细 row1「结束日期」8.6s、单号弹表 17.5s 扫描等次级热点未做内层归因，留作后续。
5. **行为零变化**：diff +263/-186 全部为 `_timing` 定义 + `with` 包裹缩进（附录 C），所有 wait/timeout 数值原样；attempt_025 实测 29/32 零 mismatch 与 attempt_024 同级。
