## 核验与正式控件

空关联明细先查存在性、类型和期望行数，`completeness=true` 不能代替行存在；反例被拒绝且保存点击为 0。系统空值规则有字段级依据：已保存样张的 API 中 9 项均为数字零，页面为只读空显示；只对公出单一对一分支及实际只读列兼容精确空字符串。缺列、错号、重复、多明细、非零分摊、格式错误及未知类型继续拒绝。原始观察和原演示结果保持原样；新 [固定回放](../automation/runs/20261023-speedup-preparation/attempt_001/evidence/system_field_semantics_replay.json) 严格通过，空明细反例仍失败。

正式 bpm_ui.py 已整合申请人优先选取与人员锁定、当前动态组件下拉、精确完整单号、关联下方金额到上方只读汇总、逐行预算与科目、原生可写账号、按完整联行号选择支行及全称回读。未使用 force/JS 点击、DOM 赋值、移除 readonly 或直接写接口。旧 run 中 review 脚本保持只读，正常入口不导入。

C1 复用已挂载原生编辑器并只缓存表列结构；增行、选单与阶段变化后失效，标题/列顺序变化重新测绘。最终完整 DOM 回读不用写入缓存。600ms 防御轮询、Tab 失焦、既有空值最多 3 次读取和全局超时均保留。阶段边界再核对计划、材料来源及配置。
