## 1 最终目标与完整范围

### 1.1 最终用户工作方式

用户只需指定**完整模板单号**，提供原始 PDF、图片、Excel 等资料及业务要求。agent 应自行完成：

1. 发现并核实当前真实登录身份，定向读取指定模板及完整相关表。
2. 盘点、理解和真实复核原件，保留页/区域/单元格定位与内容哈希。
3. 区分模板稳定资料、本次业务事实、当前系统观察和明确计算；生成复用/替换决策。
4. 按本次业务规则对账、查找必要单据、建立完整来源，生成并验证可执行计划。
5. 通过维护中的正式入口操作真实 OA 控件，填写全部应填内容。
6. 从实际 DOM 独立重读全部值、行数、身份及金额，完成独立证据审查。
7. 交付填写结果、工作簿等应交文件、核验报告、run/attempt、截图和页面状态。

用户不编写 task JSON、OCR 复核 JSON、FactSet、blueprint 或 fill-plan；这些都是 agent 内部工件。不能在“材料就绪，请用户继续生成计划”处结束。允许 agent 用模型理解非标准资料，由确定性程序负责计算、约束和网页执行；不要求另造一个无条件理解任意文件的黑盒。

材料目录名称、子目录日期和工作簿标题都不是完整期间或业务日期的证据。文件夹中已可见多个日期分组，施工时必须从 Excel、票面通行日期/区间和真实公出单确定年份、实际期间和去返方向；不将全部材料强制解释为“当前年 12 月”。开票日期不能自动替代通行日期。目录日期与票面不一致时留下差异和裁决依据。

本次冻结只接收了上述输入路径与用户规则，尚未冻结实际票数、公里数、通行费、油票总额、报销额、覆盖结论、公出单号或本案例模板号。后续 agent 必须从原件和真实系统取得，禁止在施工合同或测试里预设“应当通过”的业务答案。

## 4 本案例必须实现的业务规则

### 4.1 金额定义与严格门槛

以人民币元为统一金额单位，用 Decimal 计算，最终按实际货币精度核对：

```text
K = Excel 本次纳入范围的真实公里数合计
M = K × 1.00 元/公里
T = 本次纳入范围、去重后真实通行费票据的金额合计
R = M + T                         # Excel 中待报销总额
O = 本次有效、去重后油票的价税合计金额
F = O + T                         # 用于覆盖校验的油票 + 通行费票据总额
允许填 OA 的金额条件：F > R       # 严格大于
coverage_margin = F - R
```

必须同时报告 K、单价、M、T、R、O、F 和差额，以及各自的原件/单元格来源。等于或小于均不通过；不得把用户的“大于”改为“大于等于”，不得用显示四舍五入或浮点容差把不通过改成通过。若同一范围下 F-R 与 O-M 的复算不一致，先排查范围、去重或重复加总。

油票是本次**票据金额覆盖依据**。报销额按公里补贴加真实通行费确定，不能再把 O 作为额外费用加到 R。票据覆盖富余也不能通过增加费用、改公里数或补造行来用完。

票据必须符合本次用户供料与业务范围；不能从历史报销单、其他目录或无关业务借票补足门槛。模糊金额、重复票、作废/红字或冲销等影响真实金额的情况须核实并按实际处理，不能默认计入正额。

### 4.2 票据分类、去重与金额口径

逐份、逐页区分真实油票、真实通行费发票/收费票据、票据汇总单、行程汇总单、重复副本和其他材料。汇总单用于验证票据及行程，不能与其所汇总的发票再相加；不得把“文件数”当作“可计费票数”。

以票据唯一身份和实际票面信息去重，保留所有文件到唯一票据的映射。同票不同扫描、汇总单引用、相同金额不同票分别处理。前导零、长票号保留字符串；关键字段回原页真实复核，不以 OCR 返回值或合成 barstub 测试证明真实理解。

金额使用适合该票据的实际价税合计/实际通行金额，区分税前金额、税额、含税金额；不能混用。汇总单与独立票据数量/金额不一致时，查明缺票、重复或范围差异；未解冲突不得继续受影响的金额验收。

### 4.3 工作簿回填与复算

1. 原始文件保持只读并记录哈希。制作**保持原工作簿结构的回填副本**，作为用户这份统计表的完成版本交付；派生文件不写回原件目录。
2. 识别实际 sheet、表头、公里行、日期/路线、通行费列、公式、合计、隐藏行和备注。保留用户已统计的真实公里数、历程和不相关格式，不能根据票据路线反改公里数。
3. 每张去重通行费票据映射到准确业务行/行程。同一行多张票据须逐票列来源后求和；无法分配的票据、重复分配、跨日或同日多行歧义必须处理或登记缺口，不能平均摊分或按文件顺序填入。
4. 只将确定的真实通行费金额回填对应单元格。区分“有证据的零通行费”和“尚未找到票据”，不得用 0 隐藏缺失。
5. 复核逐行报销额与总额公式，确保实际逻辑为公里数×1元加通行费；若原公式与规则不同，保留原值/原公式并作有据修正，记录受影响单元格，不静默改业务含义。
6. 进行可靠重算并重新打开回填副本检查。公式、实际结果、逐行及总额都需与独立 Decimal 计算一致；不只读旧缓存，不以成功导出或公式文本代替结果验证。
7. 交付单元格变更清单，包含 sheet/cell、原值/公式、新值/公式、对应票据、推导及哈希；核实原件内容未变，回填副本没有损坏结构、公式和可读性。

### 4.4 必须显式建模“票据覆盖”分支

现有“每张票面金额与费用行分配完全相等”的规则不能直接套在本案例。此处 R 是按公里政策和真实通行费得到的应报额，F 是覆盖它的凭据总额，两者应严格不等。

施工须把**本案例适用的票据覆盖规则**与普通全额票面分配规则分开，在事实层、配置/schema、计划验证、独立核验和报告中保持一致。允许采用池覆盖或更细的有据模型，但必须表达：适用业务、规则来源、票据集合、公里及通行范围、R/F/差额和严格门槛。

不能删除通用票据校验、伪造免票理由、把所有票据标成不适用、把 F 改成 R，或把每张油票金额硬凑到公里行来通过旧校验。该分支的授权仅覆盖用户明确的公里报销规则，不自动放开其他部分报销、借款抵扣或未知计算场景。

## 5 真实公出单逐票匹配与 OA 随机测试关联

### 5.1 必须实际查找，不能只查关联弹窗

由唯一浏览器执行者进入真实 OA 的**公出单模块**，按原件实际申请人、年份、日期/时段、起讫地、路线和业务信息定向查询，必要时处理分页、筛选和详情。已经被历史报销使用的公出单可能不在“可关联”弹窗中；查不到可用选项不等于单据不存在。

必须留下真实模块入口、实际筛选条件、结果页及相应详情证据。可在现有受控规则内复用已观察到的只读响应辅助完整读取，但真实模块访问、页面身份和关键事实核对不能被本地缓存或接口回放替代。不普查所有人的历史，不使用直接写接口。

核对完整单号、唯一身份、申请人/工号、实际公出区间、出发/目的地、业务说明、流程状态，以及实际可观察的已关联/占用状态。未知字段为 null 并说明原因，不把“选择器未出现”推断为“已经占用”。

### 5.2 逐票对应报告

**每张去重后的真实通行费发票/票据都必须有独立匹配记录，自动查找对应公出单；不得漏掉任何一张。**每票应精确指向唯一经证据确认的目标，不能只报告若干日期或公出单总数。

报告至少包含：票据 ID、源文件/页、票号、实际通行日期/时间及路线、金额、Excel 行定位、完整公出单号/唯一身份、申请人、行程区间与路线、匹配依据、候选及排除理由、实际占用状态、详情/截图证据、最终结论。

用户要求“公出单与通行费发票一一对应”。必须展示两端完整清单、逐票对应、未匹配项、歧义项和重复引用情况，不能只凭金额或同一天即判定匹配。遇到往返分票、一个公出行程包含多段收费、同日多张公出单等情况，逐票展开真实关系和依据；不能凭数量相等强造双射，或把多票汇总成一条冒充逐票对应。实际关系仍无法满足本项要求时如实标记差异，不能擅自降低验收标准。

完整性至少核对：通行费票据清单与匹配报告票据 ID 集合相同，每票恰好一条最终匹配结论；金额合计与 T 一致；关联公出单去重数、各单对应票数和对应 Excel 行数可复算。油票参与金额覆盖，不强行要求每张油票按此规则对应某张公出单。

### 5.3 OA 随机测试关联的允许范围

本案例真实对应的公出单已经被原报销单一次性使用，**用户允许在新建测试页的关联表随机选择系统真实可选单据**，用于完成关联控件和整单内容测试；无需把已经用掉的真实对应单据重新选入，也不要求占位单与真实通行票据匹配。

明确分开两套数据：

- `actual_trip_matches`：每张去重通行费票据对应的真实公出单及详情、匹配依据、查询/截图证据。这是交给用户的真实逐票对照表，必须完整准确。
- `oa_test_relations`：OA 关联表实际选入的测试占位单及其真实系统值、选取方式、选择证据、行数和带出字段。标记 `test_placeholder`，不能作为费用归属、实际行程或真实匹配的依据。

二者可使用等价命名，但不能混用来源或在最终报告中混淆。占位单必须来自真实可选控件，仍精确选择并完整回读，不能随机编造编号、UUID、只读金额或伪造 selected 对象。关联行数不强行等于真实票数/真实公出单数，不能为凑对应关系新增无关费用。

随机关联带出的日期、人员、余额或金额属于测试单系统值；本案例费用、公里、预算适用性、R/F 计算仍来自真实案例资料。不得用占位单数据覆盖真实费用、改变应报额、填平对账差异，或把占位关联描述成已找到真实对应关系。核验分别比较实际匹配表和测试关联表各自的来源、计划及 DOM。

随机测试关联仅用于本合同、本案例材料及 `fill_only`。不保存、不提交，不释放/修改旧单关联，不重新占用已用真实单；如选取动作本身会产生即时持久占用等业务变更，停止该动作并准确报告，不以“未点保存”假定无副作用。其余可以独立完成的原件解析、真实匹配、费用填写和验证继续。

真实逐票查找/报告没有豁免。未找到、歧义未解或漏票时不能因为 OA 已随机关联就判本案例通过。未来正常新业务仍要求实际关联全部对应单据；该测试例外不得变成普通业务的全局开关。

## 6 身份、模板、来源与正式工作流

每次开工先按 `AGENTS.md` 运行登录自发现并获取 profile 锁，动态核验有效登录及当前真实人员。`--expect-name` 来自本次探查，不能硬编码某人。操作人、制单人、申请人分别记录；真实案例业务归属与默认申请人不一致时，按本次证据及合法 UI 能力处理，不能直接把同事的真实费用挂在当前登录人名下。

本地会话 JSON 按既有规则留在 Git 排除目录，不包含凭证原值。每次开工探查到期；本地 60 天只是上限，历史观察到 refresh token 签发 30 天，不保证本次仍有效或服务器最大时长。凭证只在受保护的 `.pw-profile/`，不进入材料 manifest、工件、报告或跨 agent 消息。

先定向核实用户指定完整模板号及唯一 UUID、类别、主表和全部适用子表，保存快照和哈希。模板只提供结构及适用于本次的稳定资料；费用日期、行程、公里、金额、票号和关联来自本次原件/当前系统/用户明确规则。预算年度、收款人及账号不能无条件抄旧值。每字段形成采用、替换或不适用及其依据。

原件根和派生根分别受控，全部执行值有来源定位和哈希。PDF/图片关键值回原页复核；表格单元格、公式及重算值均可追踪。推断不伪装为用户确认；有冲突时先查证，不任选一份。

正式路径必须连续衔接：

```text
请求登记与用途绑定 → 登录/身份核实 → 唯一模板确认
→ 原件清单与分类 → 全页/表格提取和真实复核
→ 行程/票据/Excel 对应 → 工作簿副本回填、重算和独立复算
→ 公出单模块逐票查找与匹配 → 票据严格覆盖校验
→ 事实、复用矩阵、可执行计划与完整验证
→ 新页预检 → 正式入口全部行填写
→ 新鲜 DOM 完整独立回读 → agent 独立复核
→ 工作簿、匹配报告、填写结论、证据和未保存页交付
```

具体准备步骤可合理排序、并行离线处理；**金额、身份、匹配及来源的必要门槛必须在正式业务写入前通过**。确有缺口时返回具体文件/页/cell/单据和影响，不能把“尚待 agent 做内部处理”包装成缺用户输入。

复用 `fill_once.py`、`bpm_ui.py`、`bpm_verify.py` 及现有材料/事实/计划模块。上层编排可以新增或改造，但正式支持场景不得依赖 run 中手写驱动、monkey patch、逐格临时命令或另一套无守卫执行器。维护 skill 必须覆盖真实 PDF/Excel 到填写交付的完整操作，不把回放 JSON CLI 当最终用户入口。

## 7 OA 填写内容与安全边界

按准确模板、本次规则和真实页面确定公里补贴、通行费的费用项目、期间、费用说明、预算、科目和收款结构；先核实每张表/列的业务含义，再建立映射。不得为了让旧执行器可用而把油票覆盖额填成应报额、挪类别、删费用或伪造只读值。

OA 应报总额、实际主要费用行合计、适用明细合计及银行收款合计均与回填 Excel 的 R 闭合。若费用说明是汇总层，与明细是同一费用的两种表示，不能相加重复报销。油票支持池、票据清单、公里和逐票匹配记录进入证据链；如 OA 某栏要求票据额而非应报额，须实证区分，不强迫所有金额栏都等于 R。

通过真实原生控件完成类别/费用项目、预算/科目、银行、适用的档案及其他选择；精确唯一命中，保留 Tab 失焦、600ms 轮询、重复稳定回读等已验证机制。evaluate 仅可用于读取与必要定位，不直接赋值表单、伪造选择对象、改变显示状态或拦截响应冒充 UI 成功。

本案例真实填写使用明确的既有案例考核用途和 `fill_only`，报告实际未保存状态；不冒称待支付新业务，不改业务日期来假装当前费用。既有旧报销单只读，不修改内容或关联。

普通 `_click_guard` 继续禁止保存、提交、发送、流转、上传、暂存、贴票和审批。`SaveController`、单次保存和 registry 保护保留，本轮不触发其保存按钮测试。未知弹框不自动确认，禁止直接写接口。

已有 `SAVE_INTENT`、`SAVE_UNCERTAIN` 或保存成功的 repo 任务只读核实，不能删除记录、换 task_id 或另建来规避。案例考核用途须和历史业务身份明确关联、与正式重报销区分，不能借“测试”绕开同任务保护。新 attempt/计划修订遵循现有绑定与恢复规则；未保存页不能因中断随意重建。

单 profile 只有一个网页执行者。不要导航、关闭其他 session 的未保存页，不强删锁、不全局终止 Chromium；原页丢失、版本漂移或不具备安全恢复能力时如实盘点并停止相关写入，继续其他独立工作。
