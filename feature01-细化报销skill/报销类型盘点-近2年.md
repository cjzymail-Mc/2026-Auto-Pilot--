## 一、技术路线

**目标**：按 制单人=运动表现研究部 拉取 BPM 报销单列表，枚举实际出现过的报销类别（submitType），近 2 年为主口径，为分类型 fill skill 定优先级。

**实现**：`list_type_query.py`（repo 根）——复用 `stage1_browser_probe` 的 profile 锁 / 浏览器启动（`--no-proxy-server`）/ 10h 登录态注入 / 扫码门 / 事件流落盘；不 import 任何填写逻辑，查询/翻页均过 NO_SAVE_WORDS 守卫（只填不存红线不破）。

**关键坑**（2026-10-23 上午 2 轮失败换来的，改脚本前先读）：

1. **PrimeNG 滚动表拆表**：表头表有 `prop-*` thead 但 tbody 空；表体表带全部行却无 thead → 行提取两步走（先从任一含 submitType 的 thead 取列序 props，再扫所有表的 tbody 按下标映射）。
2. **Angular 异步挂载**：goto 后定睡 3s 读表不稳（两轮实证 0 行）→ `wait_for_selector("th.prop-submitType")` + 1.5s 沉降。
3. **组织筛选控件**：readonly input 不可输入，触发器是 `button[aria-label='选择组织']` → `p-dialog.org-select-dialog` 内搜索选节点后点确定。

**流程**：登录态直注（免扫码）→ 列表基线 → 制单人=部门（失败回落申请部门）→ 查询 → 翻页采集全部行（按单号去重，24 页 469 行零丢失）→ 本地按制单日期 cutoff 分近 2 年 / 全量两口径聚合。

**复跑**：`python -X utf8 list_type_query.py --dept <部门>`（cwd=仓库根；换年限改脚本内 cutoff）。
