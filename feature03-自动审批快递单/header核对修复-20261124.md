# 寄件快递单自动审批：表头核对修复（2026-11-24）

## 现象

监控重启后（08:42 加载授权版本）首个真实待审单触发自动审批，13:28:44 报
`【未自动流转】快递单 13926110314｜无法核对单据编号`，页面保留人工处理；
`automation/runs/approval-watch-8e80254ab33a/events.jsonl` 记录
`approval_auto_result state=STOPPED`。STOPPED 不写 journal，重启后同单会重试。

## 根因（真实页面只读探查证据）

`tools/diagnostics/express_header_probe.py`（本次新增，只读、不点击）用与监控
同款的登录/任务中心/ApprovalWindow 打开路径复现，两轮间隔采样确认稳定：

- `qd-dynamic-form-header` 恰好 1 个，但 host 为 `display:inline` 零尺寸 box
  （rect `198,110,0,0`）→ Playwright `:visible` 判不可见 → 旧代码
  `root.locator("qd-dynamic-form-header:visible").count() != 1` 恒真，20 秒
  重试后放弃。
- header 的 `textContent` 仅「快递单」，无 input；单号 `13926110314` 实际渲染
  为 `qd-dynamic-form` 内的 `label.print-label` 文本节点。

与 2026-11-17 已知的 `qd-dynamic-table` 零尺寸 host 问题同类：当时表格检查改为
看渲染行，但 header 检查仍依赖 host 可见性；离线合成 fixture 的 header 含直接
文本（有尺寸），故 72 项离线验证无法暴露。

## 修复（bpm/approval.py snapshot）

1. header 定位去掉 `:visible`，数量不为 1 仍报「无法核对单据编号」；
2. 单号核对范围从「header 文本/inputs」扩为「header 文本（innerText+
   textContent+inputs）＋ `qd-dynamic-form` 渲染文本/控件值」，词边界正则不变；
   找不到待办单号仍报「单据页面编号与待办不一致」；
3. `qd-dynamic-form` 收集去掉 `:visible`（防御 host 零尺寸），指纹结构随之
   展平，仅影响新旧快照互比，不放宽任何拦截。

核实语义不变：组件唯一、单号一致、明细行渲染、指纹闭合、展示满 6 秒、
标准流转窗口、默认下一节点、journal 先于首次点击——全部保留。
